# Domain docs

## Layout

This repository uses a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decision records in docs/adr/.

## Consumer rules

Before exploring domain concepts, read GLOSSARY.md and ADRs
relevant to the work.

If these documents are absent, proceed silently. Domain-modeling
creates them when terms or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses, and tests.
Note missing concepts for domain-modeling.

Explicitly surface proposals that contradict an existing ADR,
including the ADR reference and reason for reconsidering it.
